# 기능 구현 11차(impl/11) 테스트 시나리오

## 1. 개요
본 시나리오는 Papers-SR-Assistant 11차 구현분의 정상 작동 여부를 검증한다.
11차 구현 범위 (PRD Phase 3, 2026-07-11 변경 이력 "실시간 다인 협업 백엔드"):
- **협업 서버** (`server/collab-server.mjs`, `ws@8`): WebSocket 공유 세션 — 세션별 last-write-wins
  상태 브로드캐스트, 첫 참여자가 상태 시드, `GET /health` 헬스 엔드포인트, 빈 세션 정리. 포트 8787 (`pnpm collab`).
- **클라이언트** (`src/api/collab.js` + App 배선): 헤더 "협업" 버튼 토글 — 세션 시작 시 참여 링크
  (`#collab=<id>`) 클립보드 복사, 참여자 수 배지, 링크 접속 시 confirm 후 참여(세션 상태로 동기화),
  로컬 변경 자동 브로드캐스트 / 원격 변경 적용 (재브로드캐스트 루프 방지), 연결 실패 시 오류 배지.
- **Vite ws 프록시**: `/collab` → `ws://localhost:8787`.

## 2. 사전 조건
- `pnpm add ws` 완료 (백엔드 구현 지시에 따른 최소 의존성), `pnpm build`/`pnpm lint` 통과.
- `pnpm collab`(협업 서버) + `pnpm dev`(Vite) 동시 기동.
- Playwright(Chromium) — **동일 브라우저의 두 페이지(A·B)** 로 실시간 동기화 검증, S2 응답 목킹, clipboard 권한.
- 원본 로그는 `logs/` 저장.

## 3. 케이스 표

| id | 목적 purpose | 입력 input | 기대결과 expected | 우선순위 |
|---|---|---|---|---|
| TC-01 | 빌드/린트 회귀 | `pnpm build`, `pnpm lint` | 빌드 성공, 신규 린트 오류 0건 | P0 |
| TC-02 | 서버 헬스 | `GET :8787/health` | `{ok:true, sessions:N}` | P0 |
| TC-03 | 세션 시작 | A: "협업" 클릭 | 배지 "협업 중 · 1명", 클립보드에 `#collab=` 링크 | P0 |
| TC-04 | 참여 + 초기 상태 시드 | B: 협업 링크 접속 + confirm (A에 사전 메모) | 양쪽 배지 2명, B 에 A 의 메모 표시 | P0 |
| TC-05 | A→B 실시간 동기화 | A: 새 메모 추가 | B 에 1초 내 자동 반영 | P0 |
| TC-06 | B→A 역방향 동기화 | B: 큐시트 항목 삭제 | A 큐시트 항목 수 감소 | P0 |
| TC-07 | 외부 논문 동기화 | A: 검색으로 논문 추가 (목킹) | B 그래프 노드 수 +1 | P0 |
| TC-08 | 참여자 이탈 | B 페이지 닫기 | A 배지 "1명" 으로 갱신 | P1 |
| TC-09 | 세션 종료 토글 | A: "협업 중" 버튼 재클릭 | 배지 "협업" (비활성) 복귀 | P1 |
| TC-10 | 서버 다운 처리 | 협업 서버 종료 후 "협업" 클릭 | "협업 연결 실패" 배지, 앱 크래시 없음 | P0 |
| TC-11 | 회귀 | 협업 종료 후 | 공유 버튼·추천·영속 정상 | P1 |
